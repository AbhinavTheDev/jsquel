# आर्किटेक्चर डिज़ाइन (Architecture Design)

`jsquel` को एक हल्के, शून्य-निर्भरता (zero-dependency) वाले SQL इंजन के रूप में तैयार किया गया है जो डेटा स्थायित्व (persistence) के लिए स्थानीय फ़ाइल सिस्टम और संरचित JSON फ़ाइलों का उपयोग करता है। यह एक अलग डेटाबेस सर्वर के परिचालन ओवरहेड के बिना परिचित SQL अनुभव प्रदान करता है।


## फ़ाइल-आधारित स्टोरेज लेआउट

डेटा को किसी मालिकाना बाइनरी कंटेनर में बंद करने के बजाय, `jsquel` डेटा को पारदर्शी, आसानी से पढ़ने योग्य और वर्ज़न-कंट्रोल करने योग्य रखता है।

सभी डेटाबेस फ़ाइलें `DATABASE_PATH` के अंतर्गत रहती हैं (डिफ़ॉल्ट रूप से `./database/` या `.env` में `MINI_SQL_DB_PATH` के माध्यम से कॉन्फ़िगर की गई)।

```
database/
├── users.schema.json         # कॉलम परिभाषाएँ और डेटा प्रकार
├── users.data.json           # JSON रिकॉर्ड्स का ऐरे
├── users.name.index.json     # "name" कॉलम पर इनवर्टेड इंडेक्स
├── products.schema.json
└── products.data.json
```

### टेबल स्कीमा (`<tableName>.schema.json`)
कॉलम परिभाषाओं को उनके अपरकेस डेटा प्रकार के साथ मैप करके संग्रहीत करता है:
```json
{
  "id": "INT",
  "name": "TXT",
  "age": "INT",
  "student": "BOOLEAN"
}
```

### टेबल डेटा (`<tableName>.data.json`)
रिकॉर्ड्स को मानक JSON ऑब्जेक्ट्स के रूप में क्रमिक रूप से संग्रहीत किया जाता है:
```json
[
  { "id": 1, "name": "Alice", "age": 28, "student": true },
  { "id": 2, "name": "Bob", "age": 24, "student": false }
]
```

### इंडेक्स फ़ाइलें (`<tableName>.<column>.index.json`)
इंडेक्स एक इनवर्टेड इंडेक्स डेटा संरचना का उपयोग करते हैं, जो त्वरित लुकअप के लिए मानों को पंक्ति सरणी इंडेक्स (row array indices) से मैप करते हैं:
```json
{
  "Alice": [0],
  "Bob": [1]
}
```


## समवर्ती और टेबल लॉक्स

एसिंक्रोनस Node.js रनटाइम या एज वातावरण में चलते समय, जहाँ कई समवर्ती अनुरोध एक साथ स्थिति बदल सकते हैं, रेस कंडीशन डेटा ओवरराइट का कारण बन सकती हैं।

`jsquel` साझा तालिकाओं पर राइट ऑपरेशन्स को क्रमित (serialize) करने के लिए टेबल-स्तरीय म्यूटिक्स लॉकिंग सिस्टम (`Mutex` और `performWithLock`) को शामिल करता है।

### `performWithLock` कैसे काम करता है

```
अनुरोध A (insert)  ───> [लॉक प्राप्त करें: users] ───> [users.data.json पढ़ें] ───> [जोड़ें और लिखें] ───> [लॉक रिलीज़ करें]
अनुरोध B (insert)  ───> [Mutex पर प्रतीक्षा करें...] ───> [लॉक प्राप्त करें: users] ───> [पढ़ें और लिखें]    ───> [लॉक रिलीज़ करें]
```

1. **अधिग्रहण (Acquisition)**: जब `performWithLock("users", fn)` को कॉल किया जाता है, तो प्रॉमिस-आधारित कतार ऑपरेशन को पंजीकृत करती है।
2. **निष्पादन (Execution)**: तालिका पर अनन्य (exclusive) पहुँच बनाए रखते हुए ऑपरेशन निष्पादित होता है।
3. **सुनिश्चित रिलीज़ (Guaranteed Release)**: लॉक रिलीज़ को एक `finally` ब्लॉक में रखा गया है, जिससे यह सुनिश्चित होता है कि क्वेरी निष्पादन के दौरान कोई त्रुटि आने पर भी कोई लॉक लीक न हो।

```js
import { performWithLock, insertInto } from "jsquel";

// सुरक्षित समवर्ती राइट्स
await Promise.all([
  performWithLock("users", () => insertInto('INSERT INTO users (id, name, age) VALUES (1, "A", 20)')),
  performWithLock("users", () => insertInto('INSERT INTO users (id, name, age) VALUES (2, "B", 22)'))
]);
```


## सर्वरलेस और एज अनुकूलता

`jsquel` उन वातावरणों के लिए अनुकूलित है जहाँ आपको PostgreSQL या MySQL जैसी पृष्ठभूमि डेमन प्रक्रियाओं को चलाए बिना एक एम्बेडेड डेटाबेस की आवश्यकता होती है:

- **शून्य डेमन्स (Zero Daemons)**: Node.js मानक मॉड्यूल (`fs`, `path`) के माध्यम से पूरी तरह से इन-प्रोसेस चलता है।
- **त्वरित कोल्ड-स्टार्ट (Cold-Start Instantaneous)**: सब-मिलीसेकंड इनिशियलाइज़ेशन, क्योंकि इसमें कोई नेटवर्क कनेक्शन हैंडशेक या डेमन सॉकेट बातचीत नहीं होती।
- **स्टेटलेस माउंट्स (Stateless Mounts)**: आसानी से पर्सिस्टेंट वॉल्यूम (AWS EFS, GCP Filestore, Docker volumes) या क्षणिक कंप्यूट कार्यों के लिए स्थानीय अल्पकालिक स्टोरेज के साथ जोड़ा जा सकता है।
- **पोर्टेबिलिटी (Portability)**: क्योंकि डेटाबेस JSON फ़ाइलों का एक फ़ोल्डर है, इसलिए बैकअप, पुनर्स्थापना और निरीक्षण केवल एक निर्देशिका को कॉपी करने या git में कमिट करने जितना आसान है।


## बैकअप और आपदा पुनर्प्राप्ति (Disaster Recovery)

एप्लिकेशन को रोके बिना किसी भी समय समकालिक (synchronously) रूप से स्नैपशॉट लिए जा सकते हैं:

```js
import { backupDatabase, restoreDatabase } from "jsquel";

// स्नैपशॉट बनाएं
backupDatabase("./backups/snapshot-01");

// आवश्यकता पड़ने पर पुनर्स्थापित करें
restoreDatabase("./backups/snapshot-01");
```
